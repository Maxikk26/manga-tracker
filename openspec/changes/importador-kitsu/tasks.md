## Phase 2: `fetch_known_slugs` + manganato sitemap parsing (Unit 2)

Signature note: the delta spec's prose says `-> Sequence[str]`, design's File Changes table says `frozenset[str]`; implemented as `frozenset` — membership over ~91k slugs is the operation's entire purpose, and a `frozenset` is not a `Sequence`. ## Phase 3: Importer pure core + loader + reconciliation writers (Unit 3, needs 1+2)

*Pure modules (export/matching/reconcile) are fully unit-testable with no I/O; `run.py` is the only orchestration layer.*

- [x] 3.1 Create `manga_tracker/importer/export.py`: parses the MAL-format XML via `ET.fromstring` (D7); status map with unmapped `my_status` as a hard error naming the value (IMP-10); `last_read_at` midnight-UTC of `my_finish_date` only when terminal and present, `NULL` otherwise, with a `0000-00-00` sentinel guard (IMP-5). Built as `parse_export(text)` + `read_export(path)`, returning `ExportEntry(external_id, status, last_chapter_read, last_read_at)` — no `my_score`, no `my_start_date`, and the module never even names the latter as a lookup string (asserted). Five guards the spec is silent on, all resolved toward failing loud and *before* the first write, so an error costs a re-run and never a half-loaded database: a missing `<manga_mangadb_id>`, a missing or non-numeric `<my_read_chapters>`, an export with zero `<manga>` entries, XML that does not parse, and an unreadable (non-sentinel) `<my_finish_date>`. The unrecognized-status error aborts the run rather than one entry — parsing precedes every write, so this is strictly louder than the requirement's "hard error for that entry".
- [x] 3.2 Create `manga_tracker/importer/matching.py` (pure): NFKD normalizer; two slug variants per candidate (apostrophe dropped/hyphenated, IMP-8); iterates `title_candidates` in order, first present-in-known-slugs wins, no later candidate tried; `is_suspect(my_read_chapters, newest_chapter)` predicate (IMP-7). All four apostrophe codepoints (`'‘’ʼ`) count as one, since a curly quote from the catalogue would otherwise produce two wrong variants instead of the right pair. `normalize` is exported for reconciliation key 3, so both sides of that comparison fold identically (D3).
- [x] 3.3 Create `manga_tracker/importer/reconcile.py` (pure): ordered three-key policy over plain values — kitsu_id / slug / normalized-title — with the exactly-one guardian on key 3 (IMP-2). Takes three *callables*, so "first hit wins" is enforced as which lookups run, not merely which answer is chosen. Interpretation recorded: KIT's "cero o más de una … queda para revisión manual" is applied as **>1 = ambiguous, 0 = create the row**. Reading zero candidates as manual review would stop the importer creating anything at all, contradicting §Carga's "Crea o reconcilia" and the measured ~136 new titles; the delta spec's only scenario for this rule is the 2-candidate one.
- [x] 3.4 In `manga_tracker/storage/repositories.py`, add `find_manga_by_kitsu_id`, `list_manga_titles`, and Kitsu writers: enrich `mangas` (backfilling `kitsu_id` when key 2/3 resolved it); bookmark writer — INSERT when absent, UPDATE only when existing `origin='kitsu_import'`, `seed`/`manual` never touched (D3, IMP-3, and v1.3's explicit extension to `manual`). `write_seed_backfill` stays untouched. "Only when the catalogue supplied it" is expressed as `COALESCE(?, column)`, which keeps the SQL static and parameterized; `kitsu_id` is COALESCEd the other way (`COALESCE(kitsu_id, ?)`) so an id already stored is backfilled-when-missing and never repointed. Added `find_manga_site_for_manga`, because `(manga_id, site_id)` is UNIQUE and a row reconciled by key 1 may already be mapped to a different slug — without the check that entry would abort the whole run on an integrity error. None of the new writers commit; the caller owns the transaction.
- [x] 3.5 Create `manga_tracker/importer/run.py`: per entry, inside one `db.transaction(conn)`, `fetch_chapters` → verify (IMP-7) → reconcile+write, so a suspect match leaves zero rows (D5); terminal entries skip the slug lane, zero requests (IMP-4); `NotFound`/`Unexpected`/`Transient`/zero-chapters per entry → pending, continue to next entry, never abort the run (IMP-9); `[i/total] 'Title' ...` with `flush=True` before each `fetch_chapters` call (D4). Returns `ImportReport(total, loaded, pending)` with `PendingEntry(title, last_chapter_read, status, reason)`; writing the CSV is Phase 4's, so this stays testable with no filesystem. Load order is `want_to_read → on_hold → reading → terminals`: the one-pager ranks only the first two, `reading` is unranked by both documents and terminals generate no manual work at all. Two further spec-silent guards, both toward reporting rather than guessing: a catalogue entry resolved to an empty title (its normalized form would match every other untitled row on key 3) and the mapping conflict from 3.4.
- [x] 3.6 In `run.py`, call `fetch_known_slugs()` once before matching any entry; if it raises, propagate and abort the whole run with zero rows written anywhere — do NOT route it to per-entry pending. Called unconditionally after catalogue resolution and before the loop; nothing catches it. (KIT v1.3: a lost unit is ~10k missing slugs, and catching it per entry would push real titles to pending as if the source did not carry them.)
- [x] 3.7 Write `tests/importer/test_export.py` (19 tests) + fixtures `tests/fixtures/kitsu_export_small.xml` (6 entries: all five statuses, one with a finish date, one with none, one non-terminal deliberately carrying a finish date, one `0000-00-00`) and `kitsu_export_unmapped_status.xml`. ### Phase 3 mutation evidence

Every guard added in this phase was broken one at a time, the full suite run, and the mutation reverted — 39 mutations, 39 red, each one confirming the *intended* test failed and not merely some test. The script lives outside the repo. What was injected, by module:

- **`export.py` (10)**: default an unrecognized status to `reading`; accept a missing MAL id; default a missing or non-numeric progress to 0; drop the zero-entries guard; swallow the XML parse error; replace the parse message with a generic one (proves the test pins that branch's text, not just `ExportError`); drop the `0000-00-00` sentinel from the guard (the malformed-date guard then fires instead — caught because the assertion names the sentinel case); null a malformed date silently; read `my_finish_date` for non-terminal entries too.
- **`matching.py` (6)**: emit only the apostrophe-dropped variant; skip the combining-mark drop; sort the candidate list; return the *last* match instead of the first; make `is_suspect` non-strict (`>=`); remove the no-progress guard.
- **`reconcile.py` (3)**: evaluate keys 2 and 3 eagerly before key 1; let key 3 fire on any number of candidates; drop the backfill flag from a key-2 match.
- **`repositories.py` (7)**: replace `COALESCE(?, column)` with a plain assignment; reverse the `kitsu_id` COALESCE so a stored id is repointed; disable the non-`kitsu_import` bookmark protection; write `progress_is_approx = 0`; drop `OR IGNORE` from the `chapter_history` insert; set `detected_via` to `feed`; return `"[]"` instead of NULL for an empty list.
- **`run.py` (13)**: skip the suspect check; drop the terminal short-circuit; narrow the per-entry `except` to `NotFound` only; drop the zero-chapters guard; swallow the `fetch_known_slugs` failure; touch the source before resolving the catalogue; drop the ambiguity guard; drop the mapping-conflict guard; drop the empty-title guard; print the announcement *after* the request; drop the load ordering; replace `db.transaction(conn)` with a no-op; import `sources.manganato` (fails the boundary test).

One finding this pass produced, and it is the reason the pass is worth running: sorting the candidate list left `test_candidates_are_generated_in_the_order_the_catalogue_supplied_them` **green**, because its example names (First/Second/Third) sort into the very order they were supplied in. The guard was covered only incidentally by a neighbouring test. Both order-sensitive tests now use names that are not in alphabetical order, and the mutation kills the intended test. One honest limitation: removing the `if not last_chapter_read` guard in `is_suspect` turns the test red only through its `None` parameter — for `0` the comparison `0 > 30` is False on its own arithmetic, so that branch of the guard is defence in depth rather than behaviour under test.
